Partition-Folded Oracle Ingestion & Fabric OneLake Gold Pattern

Problem

Manual CSV extracts and full-table reloads from partitioned Oracle ERP tables created 30+ hours/month of reporting lag and nested-subquery bottlenecks before finance and ops reviews.

Constraint

Production ERP databases could not tolerate unindexed full-table scans or locks during business hours, while newer Fabric workloads needed Delta Parquet V-Order readiness.

My Decision & Outcome

I separated the two storage architectures cleanly: for Oracle → Power BI Import, I exposed a deduplicated ROW_NUMBER() view keeping transaction_timestamp unwrapped so Power Query RangeStart/RangeEnd partitions fold to Oracle partition pruning; for Fabric Direct Lake evaluation, I authored an incremental PySpark MERGE INTO pipeline resolving integer surrogate keys with V-Order and Liquid Clustering.

technical-showcase/sql/oracle_incremental_staging_cte.sql 
-- Foldable view: Power Query RangeStart/RangeEnd filters push to Oracle partition pruning
CREATE OR REPLACE VIEW erp_owner.vw_sales_latest_revision AS
WITH RankedTelemetry AS (
  SELECT t.transaction_id, t.customer_account_id, t.store_id,
         t.transaction_timestamp,
         CAST(TO_CHAR(t.transaction_timestamp, 'YYYYMMDD') AS NUMBER(8)) AS date_key,
         t.net_amount_eur,
         ROW_NUMBER() OVER (PARTITION BY t.transaction_id ORDER BY t.revision_sequence DESC) AS row_rank
  FROM erp_owner.sales_transactions_partitioned t
  WHERE t.status_code IN ('SETTLED', 'POSTED', 'AUDITED')
)
SELECT transaction_id, customer_account_id, store_id, transaction_timestamp, date_key, net_amount_eur
FROM RankedTelemetry WHERE row_rank = 1;
